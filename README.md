# CS 230 Portfolio Reflection

The Gaming Room was the client for this project. They had an existing Android game called Draw It or Lose It and wanted to expand it into a web-based application that could work across multiple platforms. The software needed to support multiple teams and players, unique game and team names, secure access, and a scalable client-server design.

One thing I did well in this documentation was organizing the client’s requirements into clear design constraints and recommendations. I explained why a Linux-based cloud server, browser-based client access, and distributed architecture would be a good fit for the client’s needs.

Working through the design document helped me understand the code better because it forced me to think about the system before implementation. It helped me plan the domain model, game objects, storage needs, memory management, security, and platform support.

If I could revise one part, I would improve the system architecture view by adding a simple diagram showing how the client devices connect to the server, database, and storage system. That would make the design easier for a nontechnical client to understand.

I interpreted the user’s needs by focusing on cross-platform access, reliable game-state management, security, and scalability. Considering user needs is important because the software must solve the client’s actual problem and provide a good experience for players.

My approach to designing software was to break the problem into smaller parts: requirements, constraints, domain model, platform evaluation, and recommendations. In the future, I would continue using this method, along with UML diagrams and design patterns, to analyze and design similar applications.
