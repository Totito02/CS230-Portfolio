# CS 255 System Analysis and Design Portfolio

## DriverPass Project Reflection

### Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?

The client for this project was DriverPass. They wanted a system that would help students prepare for their driving tests through online practice exams and on-the-road driving lessons. The system also needed to support scheduling, user accounts, different employee roles, progress tracking, and administrative functions.

### What did you do particularly well?

I think I did particularly well at identifying the different requirements from the DriverPass interview and turning those requirements into a system design. I also learned how UML diagrams can be used to show different parts of a system and communicate how the system should work.

### If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would improve some of my UML diagrams. I would review the relationships and flow again and add more detail where necessary. I would also make sure the diagrams remain simple and easy for another developer to understand.

### How did you interpret the user's needs and implement them into your system design? Why is it so important to consider the user's needs when designing?

I reviewed the DriverPass interview and identified what each type of user needed from the system. I then used those requirements when creating the system functions and UML diagrams. Considering the user's needs is important because a system can work technically but still fail if it does not solve the customer's actual problems or is difficult to use.

### How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?

I would start by understanding the problem and collecting the requirements before designing anything. I would identify the users, functional and nonfunctional requirements, and then break the system into smaller processes. I would use UML diagrams to visualize the design and review the design with the client and development team. I would also continue improving the design as new information or feedback becomes available.
